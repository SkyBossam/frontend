# 16. 위험 감지 상세 모달

- **경로:** `공통 오버레이`
- **목적:** 위험 설명과 다음 행동을 우선 전달
- **화면 기준:** 최종 보라/노랑 목업(라벤더 배경·흰 카드·큰 CTA)

## UI 구성
- 빨간/노랑 상태 헤더 `즉시 확인 필요` 등.
- 감지된 이벤트 종류·시각·아이 이름·화면 캡처(권한/정책 허용 시).
- 명확한 다음 행동 하나: 예) “아이의 얼굴 주변 침구를 직접 확인해 주세요.”
- 1차 CTA `지금 확인하러 가기`, 2차 `닫기`.
- 확인 결과 영역: `상황 확인 중`, `위험 요소 제거함`, `오탐/문제 없음`, `확인 불가`.

## 인터랙션 및 이동
- CTA → 모니터링 또는 보호자 현장 확인 안내, status는 `checking`/`acknowledged`까지만.
- 현장 확인 후 결과를 명시적으로 제출해야 `resolved` 처리.
- 닫기는 이벤트를 해결 처리하지 않음.

## 데이터/상태 및 예외
- 안전성 한계: 시스템이 감지하지 못해도 위험이 없다는 의미는 아님.
- 화면을 닫아도 미해결 위험은 홈에 유지.
- 긴급 알림 권한 제한 시 앱 내 배너 노출.

## 구현·검수 포인트
- 로딩/빈 상태/오류/접근성을 공통 컴포넌트로 처리.
- 저장·선택 결과는 실제 상태에 반영하고 성공 전에는 완료로 표시하지 않음.
