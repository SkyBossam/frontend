# 아이쿠 (aicoo)

보라·노랑 파스텔 모바일 목업과 첨부된 17개 화면 명세를 바탕으로 만든 React + TypeScript 프론트엔드입니다. 모바일에서는 하단 탭, 데스크톱에서는 사이드 메뉴와 2열 대시보드를 사용합니다.

## 실행

Node.js 22 이상에서 프로젝트 폴더를 열어 실행합니다. Windows PowerShell에서는 실행 정책에 영향받지 않는 `npm.cmd`를 사용할 수 있습니다.

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

브라우저에서 터미널에 표시된 로컬 주소를 엽니다. 첫 화면의 **지안이의 하루 미리 둘러보기**로 시연 데이터를 확인할 수 있습니다.

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run preview
```

## 구현 범위

- 시작, 실제 회원가입/로그인, 서버 아이 등록·수정, 로컬 사진 선택, 알림 설정·소리 테스트
- 대시보드, 일별 요약, 아이 관리, 루틴 추가·수정·삭제·완료
- 울음 목록·기간 필터·상세, 추천 행동, 복수 행동 선택, 4가지 반응, 중복 방지 저장과 결과 조회
- 모니터링의 미연결·재연결·화면 가림 상태, 미연결 센서, 위험 상세·현장 확인 결과
- 설정, 기록 JSON 다운로드, 로그아웃, 키보드 접근·모달 포커스 제한, 반응형 레이아웃
- 더보기의 시연 도구로 얼굴 가림 알림 및 AI 분석 실패 상태 확인
- `/devices`: 로그인한 아이쿠 계정의 이메일 인증, 아이 등록·선택, 기기 코드 확인·승인, 기기 상태 조회·연결 해제

## 아이쿠 연결하기

백엔드를 `http://127.0.0.1:8080`에서 실행한 뒤 `npm run dev`로 프론트를 시작합니다. 개발 서버가 `/api/v1`을 백엔드로 프록시합니다. 시작 화면에서 **로그인** 또는 **회원가입** 후, **모니터링 → 아이쿠 연결하기** 또는 **더보기 → 아이쿠 연결하기**를 엽니다. 시작 화면에는 연결 버튼이 없습니다.

배포 시에는 `.env.example`을 참고해 `VITE_API_BASE_URL=https://실제-백엔드-origin`을 빌드 전에 지정하세요. 백엔드 안내에서 복사한 주소에 `/api` 또는 `/api/v1`이 붙어 있어도 중복하지 않고 정규화합니다. 백엔드의 `CORS_ORIGINS`에는 이 프론트의 origin을, `FRONTEND_URL`에는 QR 링크를 열 프론트 주소를 설정합니다. 빈 API 주소는 같은 origin을 사용하므로 프록시 없는 정적 호스팅에서는 실제 API 주소 설정이 필요합니다. `/login`, `/signup`, `/devices`도 SPA fallback 대상에 포함하되 `/api/v1` 요청은 백엔드로 전달해야 합니다.

1. 파이에서 `aicoo_device.py pair`를 실행합니다.
2. 보호자가 앱에 로그인하고 **아이쿠 연결하기**를 엽니다. 연결 화면에서 다시 로그인할 필요는 없습니다. 이메일 인증이 안 되어 있으면 먼저 인증합니다. 로컬 백엔드는 실제 메일 대신 개발용 인증 코드를 화면에 표시합니다.
3. 돌봄 공간·아이를 선택하고 8자리 코드를 입력합니다. 아이가 없으면 등록합니다.
4. 파이와 화면의 기기 확인값을 대조하고 **이 아이에게 연결**을 누릅니다.
5. 파이에서 `aicoo_device.py run`을 실행하면 기기 목록이 온라인으로 갱신됩니다.

파이 설치·자동 실행 안내: [backend/raspberry-pi](https://github.com/SkyBossam/backend/tree/main/raspberry-pi). 연결 코드는 5분 유효하며, `#code=ABCD-2345` 링크는 코드만 미리 채우고 자동 승인하지 않습니다. 로그인 전 QR 링크나 `/devices`에 직접 접근하면 `/login`으로 이동하며, 로그인·회원가입 후 같은 코드로 연결을 이어갑니다. 체험 계정도 실제 연결 전에는 아이쿠 로그인이 필요합니다.

기기별 인증 토큰은 브라우저에 전달하지 않습니다. 사용자 인증 토큰은 앱 공통 메모리에서 관리하므로 페이지를 이동해도 유지됩니다. 새로고침하거나 로그인 세션이 만료되면 다시 로그인합니다. 사용자 로그아웃은 이미 등록한 파이를 해제하지 않습니다. 온보딩에서 등록한 아이는 서버에 저장되어 연결 화면에서 바로 선택할 수 있습니다.

기기 목록은 5초마다 실제 서버 응답을 조회합니다. **온라인은 파이의 통신 상태**이며 영상 재생이나 아이의 안전을 의미하지 않습니다. 해제 후 다시 연결할 때는 파이에서 새 코드를 발급합니다.

## 현재 데이터와 연동 범위

**앱 로그인·회원가입·아이 이름과 생년월일·기기 연결과 Sky Eye 모델 관측 결과가 실제 백엔드와 연결됩니다.** 홈의 안전 상태 및 모니터링의 자세·얼굴·울음·돌봄 힌트는 기기가 전송한 데이터입니다. 모델의 추론 자체는 파이에서 실행합니다. 울음 이력·수면 기록·루틴·보호자 대응 결과는 PostgreSQL에 저장되고, 아이 사진·성별·환경 설정은 로컬 저장소를 사용합니다.  카메라 미리보기는 기기 인증을 거쳐 최대 2fps로 표시하며 음성 재생은 포함하지 않습니다. **지안이의 하루 미리 둘러보기**는 별도의 체험 데이터입니다. Apple/Google 로그인 버튼은 공급자 연결 전까지 표시하지 않습니다.

로그인하면 아이의 DB 기록을 조회하며 화면을 보고 있을 때 20초마다 갱신합니다. 화면 위 새로고침으로 바로 다시 읽을 수 있습니다. 저장 실패 시 완료로 처리하지 않으며 입력을 유지합니다. 새로 로그인하거나 다른 브라우저에서도 같은 계정·아이의 기록이 복원됩니다. localStorage는 최근 조회 사본이고 체험 기록은 별도 `demo` 공간에만 보관됩니다. 기존 로컬 수면·루틴은 원본을 `aicoo-v1:records-backup:` 키로 백업한 뒤, 아이가 일치하고 UUID와 시간 값이 유효한 항목을 한 번 이관합니다. 시작 시간이 없는 이전 루틴은 백업에 남으며 새 루틴으로 시간을 입력해야 합니다. 실제 인증 토큰·비밀번호는 localStorage나 sessionStorage에 저장하지 않습니다. 이전 체험 로그인 이메일만 남아 있어도 실제 로그인으로 취급하지 않습니다. 다른 아이를 선택하면 이전 아이의 로컬 기록을 새 아이의 기록으로 표시하지 않습니다.

카메라가 없을 때 안전을 단정하지 않으며, 온·습도 값도 임의 생성하지 않습니다. 위험 모달 열람·닫기·모니터링 이동은 해결 처리와 분리됩니다. `위험 요소 제거함` 또는 `오탐 / 문제 없음`을 명시적으로 저장해야 해결됩니다. 체험 데이터는 실제 모델 결과와 분리합니다. 실제 돌봄 힌트의 점수는 상대 가중치로만 표시하며 울음 원인의 확률이나 진단으로 해석하지 않습니다.

`docs/`는 제공받은 원본 명세를 보존한 폴더입니다. 원본의 BabySense 명칭은 구현 화면에서 사용자 요청에 따라 **아이쿠(aicoo)**로 변경했습니다. API 계약은 `docs/data-contracts.md`를 참고하세요.

## 울음·하루 기록

- 파이의 울음 후보 시작·종료가 같은 울음 이력으로 합쳐집니다. 학습용 에피소드 구간은 울음 횟수에 중복 집계하지 않습니다.
- **우리 아이 → 하루 흐름 → 수면 기록 추가**에서 실제 수면 시간을 입력하고, 기록을 눌러 수정·삭제합니다. **루틴 추가**에서는 계획과 완료 상태를 관리합니다. 수면 계획은 실제 수면 시간으로 자동 계산하지 않습니다.
- **울음 관리 → 상세 → 시도 행동·반응 기록**은 DB에 저장합니다. 이 돌봄 일지는 모니터링의 모델 학습 피드백 명령과 별개입니다.
- **이력보기**에서 한국 날짜 기준 울음 횟수·실제 수면 시간·완료 루틴을 확인합니다. 자정을 넘는 수면과 겹치는 구간도 계산합니다.
- 다른 화면에서 먼저 수정한 기록은 덮어쓰지 않습니다. 충돌 안내 후 최신 기록을 다시 열어 주세요.
- 기기를 해제하거나 새 아이에게 연결해도 과거 이력은 원래 아이에게 남습니다.

## 커밋 구성

초기 화면은 공통 기반부터 테스트·문서까지 페이지별 19개 커밋으로 구성했습니다. 이후 기기 연결 API·연결 화면·실행 안내를 기능별 커밋으로 추가합니다.

배포 사이트의 ChatGPT 로그인 요구는 Sites 공개 설정에서 해제되어 있습니다. 앱 내부 로그인은 아이쿠 백엔드 인증을 사용합니다. GitHub 저장소에는 개인 Sites 배포 식별자와 실행 환경 파일을 포함하지 않습니다.

## 로그인 404 확인

- 정상 요청 경로는 `POST /api/v1/auth/login`입니다.
- 로컬에서는 프론트와 백엔드를 모두 실행하세요. 백엔드 주소를 확인하려면 `http://127.0.0.1:8080/actuator/health`를 엽니다.
- 정적 호스팅에는 API 서버가 포함되지 않습니다. `VITE_API_BASE_URL`을 설정하고 다시 빌드·배포하거나, 같은 origin의 `/api/v1`을 실제 백엔드로 프록시해야 합니다.
- `/api/v1/api/v1/auth/login`처럼 API 경로가 중복되던 경우는 클라이언트에서 자동 정규화합니다. 백엔드 자체가 없거나 잘못된 서버 주소는 이 정규화로 해결되지 않습니다.

## Sky Eye 모델 연동

백엔드의 [파이 실행 안내](https://github.com/SkyBossam/backend/blob/main/raspberry-pi/SKY_EYE.md)를 따라 `bash ~/backend/raspberry-pi/start-aicoo.sh`를 실행하세요. 이미 코드 승인을 완료했다면 서버 주소와 기기 키를 다시 입력하지 않고 데이터·카메라 전송이 이어집니다. 로그인 후 연결한 아이의 **모니터링**에서 울음 후보, 자세·얼굴 관측, 최근 30개 기기 이벤트와 실험적 돌봄 힌트를 봅니다. 정상 종료된 울음에 실제 행동을 기록하면 파이로 전달하고 모델 처리 영수증을 확인한 뒤 완료로 표시합니다.

- 실제 피드백 10건과 현재 울음 10창 및 모델 ready 조건을 모두 충족해야 추천합니다. 시뮬레이션은 표시하지 않습니다.
- 상태는 약 2.5초마다 조회하며, 입력/응답이 오래되거나 네트워크가 끊기면 확인 불가로 바뀝니다. 계정·아이 변경 시 이전 요청 결과를 버립니다.
- 홈과 모니터링의 안전 상태는 실제 기기 값입니다. 기존 체험 자세 팝업·하루 흐름 UI도 유지합니다.
- 과거 이벤트는 새 알림으로 발송하지 않습니다. 최근 시작 관측은 앱이 열린 동안 알림에서 확인합니다. 모바일 백그라운드 푸시는 포함되지 않습니다. 카메라 미리보기는 로그인과 아이별 영상 권한으로만 볼 수 있으며, 오래된 프레임은 지웁니다.
- 실제 기기 기록은 모니터링에서 확인합니다. 기존 울음 상세·행동 흐름은 수동/체험 기록입니다.

검증: `npm test` / `npm run build`. `tests/skyEye.test.ts`는 시각 만료, 클라이언트 시계 차이, 시뮬레이션·추천 조건과 이벤트 상태를 검증합니다.

기기 목록은 연결 승인과 실제 파이 응답을 구분합니다. 승인 후 데이터가 없으면 `연결 승인됨 · 파이 실행 대기`와 실행 명령을 안내합니다. 모니터링의 영상과 AI 분석 상태도 별도 표시합니다. 영상이 보여도 아이가 감지되지 않거나 신뢰도가 낮으면 분석은 확인 불가일 수 있습니다.
